# 333 多蓝图拆分方案 — 设计规范

## 来源

外部 Satisfactory Calculator 生产图（仓库根目录文件 `333`）的 factory-plan 多蓝图实现方案。

本设计不直接修改 `data/schemes/*.json`，只定义如何把 `333` 的整套生产链拆分到多个 `4×4` 蓝图中，并为后续实现提供稳定的接口边界和布局原则。

## 目标

- 把 `333` 对应的整套产线拆分为 **5 个蓝图**
- 每个蓝图占地 **4×4 foundation（32m × 32m）**
- 每个蓝图总高按 **64m** 规划，但按用户确认，**单个机器层可用高度按 24m 计算**，剩余高度视为楼板/天花板空间
- **矿机不计入蓝图**
- 所有终端产物最终进入 **1 个统一总出口蓝图**
- 优先目标是 **让蓝图之间接线容易落地**，而不是追求最少蓝图数量

## 已对齐约束

1. 方案为 `333` 定制，不要求抽象成可复用通用模块
2. 矿机和原矿节点不放进蓝图，只保留外部物料接口
3. 目标蓝图数控制在 `4-6` 个之间，当前定为 `5`
4. 整套方案最后必须有一个统一合流出口
5. 宽/长/高、端口偏移、clearance 高度，以 `src/core/registry.ts` 为唯一占地真值
6. 配方速率以 `333` 当前数据为主，必要时可用官方 wiki 交叉核对，但不以外部 wiki 的占地说法指导布局
7. 设计重点是减少跨蓝图乱接、减少无意义的 splitter/merger、降低 belt 穿模风险

## 关键判断

整套方案的难点不在于机器绝对放不下，而在于铁系前段特别是 `iron-rod -> screw` 这段物流很容易把蓝图内部做成中央总线地狱。

因此，本设计采用以下总策略：

- 把最容易打结的铁系预处理尽量留在同一个蓝图中解决
- 跨蓝图只传递语义明确的“已整理物料”或“半成品”
- 不让 `BP2` 同时承担基础件生产、复杂分流和装配三种复杂度
- 让 `BP4` 保持纯终装蓝图，不回头承担前段基础件加工

## 蓝图划分

| 蓝图 | 职责 | 主要内容 |
|---|---|---|
| `BP1` | 铁系预处理总成 | 冶炼 + 铁板 + 铁棒 + 螺丝 |
| `BP2` | 铁系装配 | 强化铁板 + 转子 + 模块化框架 |
| `BP3` | 铜钢件 | 电线 / 电缆 / 铜板 / 混凝土 / 钢梁 / 钢管 / 定子 / 钢筋混凝土梁 |
| `BP4` | 终装 | 马达 + 重型模块化框架 |
| `BP5` | 总出口 | 15 路终端物料统一合流为 1 路外输 |

## BP1 设计

`BP1` 是整套方案中最复杂的蓝图，但它承担这种复杂度能换来整套方案最稳定的接口结构。

### BP1 Layer A

`Layer A` 继续承担生产任务，而不是只做冶炼。

放置内容：

- `2 × smelter`（铁锭）
- `1 × smelter`（铜锭）
- `1 × foundry`（钢锭）
- `1 × constructor`（铁板）
- `3 × constructor`（铁棒）

这一层只做两类事：

- 把外部原矿转换成锭和基础件
- 把需要进一步整理的物料送到上层

这一层不做复杂的总线分发，不允许 belt 在机器中区横穿。

### BP1 Layer B

`Layer B` 是物流夹层，同时继续承担螺丝生产。

放置内容：

- `2 × constructor`（螺丝）
- 必要数量的 `splitter / merger / lift`
- `BP1 -> BP2` 与 `BP1 -> BP3` 的固定立面接口

这一层只允许做 4 件事：

1. 接住 `Layer A` 上送的铁板、铁棒、铜锭、钢锭
2. 在本蓝图内完成 `iron-rod -> screw` 的局部闭环
3. 进行必要且克制的一次分流/合流
4. 从固定立面把物料送往下游蓝图

这一层不再放新的铁板/铁棒生产机，也不做无边界的中央总线。

### BP1 接口纪律

`BP1 -> BP2` 输出：

- `铁板` 1 路
- `铁棒` 2 路
- `螺丝` 1 路

其中两路铁棒分别服务于：

- `Rotor`
- `Modular Frame`

`BP1 -> BP3` 输出：

- `铜锭`
- `钢锭`

这里的重点不是把接口压缩到最少条数，而是让每条接口的语义稳定。
`BP2` 收到的应该是已经整理好的铁系输入，而不是“进蓝图后还要重新拆一次的大总线”。

## BP2 设计

`BP2` 被定义为纯铁系装配蓝图。

### BP2 Layer A

`Layer A` 只做入料整理、短距离分发和必要上送，不再放铁棒或螺丝生产机。

它更像一个轻量的缓冲层：

- 接住来自 `BP1` 的板、棒、螺丝
- 根据三台装配机的需求把物料送到正确位置
- 避免 belt 直接穿过装配机区域

### BP2 Layer B

放置内容：

- `1 × assembler`（强化铁板）
- `1 × assembler`（转子）
- `1 × assembler`（模块化框架）

建议布局：

- `强化铁板` 与 `转子` 并排
- `模块化框架` 独占一侧

这样做的原因是：

- `强化铁板` 和 `转子` 共享对螺丝的重依赖
- `模块化框架` 同时需要铁棒和强化铁板，和前两者的物料方向不同
- 把 `模块化框架` 单独隔开，可以减少装配层内部交叉

### BP2 设计收益

- `BP2` 不再承担基础件生产
- `BP2` 不再承担 `rod -> screw` 复杂回转
- 绝大部分 belt 调整会集中在 `BP1 Layer B`，而不会扩散到整个铁系装配逻辑

## BP3 设计

`BP3` 负责铜链、钢链和混凝土链，并在本蓝图内尽量闭环到中间件和终端件。

主要内容：

- `Wire`
- `Cable`
- `Copper Sheet`
- `Concrete`
- `Steel Beam`
- `Steel Pipe`
- `Stator`
- `Encased Industrial Beam`

### BP3 接口原则

`BP3` 对外只输出两类东西：

1. 终端产物，直接送 `BP5`
2. `BP4` 真正需要的半成品，如：
   - `Stator`
   - `Steel Pipe`
   - `Encased Industrial Beam`

`BP3` 不应把 `wire`、`beam`、`pipe` 这种基础件大面积外抛给其他蓝图二次处理。

## BP4 设计

`BP4` 保持纯终装角色，只放：

- `Motor`
- `Heavy Modular Frame`

它只接受来自前两段已经整理好的半成品：

来自 `BP2`：

- `Rotor`
- `Modular Frame`
- `螺丝`

来自 `BP3`：

- `Stator`
- `Steel Pipe`
- `Encased Industrial Beam`

`BP4` 不接铁锭、铁棒、电线等基础件。

这能保证：

- `BP4` 的职责稳定
- 终装蓝图不会反过来吞掉前段物流复杂度
- 后续排查马达或 HMF 问题时，边界更清楚

## BP5 设计

`BP5` 只负责统一收货与总合流，不参与生产分配。

输入为整套方案的 `15` 路终端物料，输出为 `1` 路总外输。

`BP5` 存在的意义是：

- 让前面四个蓝图不必为了“最后怎么汇总”互相让位
- 把总出口逻辑集中到一个独立蓝图里
- 让终端输出层和生产层解耦

## 跨蓝图接口规则

整套方案只允许以下 5 类跨蓝图流向：

1. `BP1 -> BP2`：铁系整理后物料
2. `BP1 -> BP3`：铜锭 / 钢锭
3. `BP2 -> BP4`：铁系半成品
4. `BP3 -> BP4`：铜钢半成品
5. `BP2 / BP3 / BP4 -> BP5`：最终产物

不允许出现以下情况：

- 同一条接口带同时承担基础件和终端物料
- 蓝图临时从非约定立面进出
- 为了省一条 belt，在下游蓝图入口重新做一次大拆分

## 走线原则

### 总原则

- 不做中央大总线
- 不做“先总合再总分再总合”的重复物流
- belt 优先走边缘立面和短走廊
- 机器输入从背面接口带进入，尽量减少穿越机器占地区域

### BP1 重点

- `iron-rod -> screw` 只在 `BP1` 内解决
- 两台 `screw` 机应靠近各自的 rod 入口
- 如果必须合流，只在离开蓝图前或离开局部闭环前做最后一次合流

### BP2 重点

- 装配层不允许再出现 rod/screw 生产回转带
- `RIP` 与 `Rotor` 的共享螺丝带只允许经过装配区一次
- `Modular Frame` 单独占位，避免与 `RIP` 输出线交叉

### 跨蓝图重点

- 所有跨蓝图 belt 默认走固定立面
- 不允许“左进右出再绕背面”式临时接法
- 下游蓝图要以“接收已整理物料”为前提设计入口，而不是期待上游输出一条混合总线

## 实施导向

本设计服务于后续 implementation plan，推荐按以下顺序实现：

1. 先实现 `BP1`
2. 再实现 `BP2`
3. 然后实现 `BP3`
4. 再实现 `BP4`
5. 最后实现 `BP5`

原因：

- `BP1` 接口一旦稳定，`BP2` 的难度会明显下降
- `BP3` 与铁系拆分开，适合独立推进
- `BP4` 依赖 `BP2 + BP3` 的半成品接口，应放在后面
- `BP5` 只依赖最终产物，最适合最后统一收口

## 验收导向

后续实现时，除了项目已有规则外，本设计特别强调以下验收标准：

- 蓝图职责边界保持稳定，不因临时绕线破坏接口语义
- `BP1` 虽复杂，但复杂度必须留在本蓝图内部，不外溢到 `BP2`
- `BP2` 必须保持“装配为主”的角色
- `BP4` 必须保持“终装为主”的角色
- `BP5` 不得反向承担生产中转职能
